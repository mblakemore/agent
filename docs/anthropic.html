Anthropic API backend

Anthropic API backend

Source: docs/anthropic.md

The agent can run on the Anthropic API directly, billed to your API account's credits. Backend kind: anthropic (aliases claude, anthropic-api). It shares the AI Commons backend's Messages API path, so it gets the same native tool calling, streaming, thinking, effort and prompt caching.

Quick start

export ANTHROPIC_API_KEY="<your key>"      # from platform.claude.com/settings/keys
agent --backend-main anthropic --backend-summary anthropic "your task"

Without a configured model, the defaults are claude-sonnet-5-5 for main and claude-haiku-5-5 for summary. --model picks another main model, and --effort sets its reasoning effort (low, medium, high, xhigh, max).

Or run /setup and pick Anthropic API. It uses ANTHROPIC_API_KEY when it is set; otherwise it asks for a key and saves it in .agent/config.json (mode 600). Then it lists the models your key can use.

Credentials

Resolved in this order:

  1. The role's own api_key in backends.
  2. The shared anthropic block at the top of .agent/config.json.
  3. ANTHROPIC_API_KEY.
  4. Whatever the anthropic SDK finds by itself: ANTHROPIC_AUTH_TOKEN, or a profile saved by ant auth login.

base_url (or ANTHROPIC_BASE_URL) points it at another Messages API endpoint.

Config

{
  "anthropic": { "api_key": "<key>" },
  "backends": {
    "main":    { "kind": "anthropic", "model": "claude-opus-5-5", "effort": "high" },
    "summary": { "kind": "anthropic", "model": "claude-haiku-5-5" }
  }
}

The keys from the AI Commons config table apply here too (thinking, effort, max_context_tokens), except the quota and catalog keys. max_request_bytes defaults to 30 MB, under the API's 32 MB limit.

How it differs from AI Commons

  • Model limits come from the API. At startup the agent reads the model's context window, output limit and thinking support from GET /v1/models/{id}. There is no hand-kept model table.
  • No allowance polling. Spend and limits are in the Claude Console. When the account runs out of credits, the agent stops with a "credit balance is too low" message (or fails over to another backend if one is configured).
  • Thinking blocks survive history edits. The API signs each thinking block against the conversation before it. When the context window fills, the agent drops old turns, and /system changes the system prompt. On accounts that enforce the check, either would make later requests fail. So every request asks the API to drop thinking blocks that no longer match (prefix_mismatch_behavior: "drop_block", beta thinking-binding-controls-2026-08-01) instead of rejecting the request.

Prompt caching, effort escalation, the session log lines (anthropic.cache, anthropic.session) and error handling work as described on the AI Commons page.
